# 2026 年 2-4 月短信电话召回会员付费分析报告

## 1. 核心结论

2026 年 2-4 月短信电话召回用户的会员短期付费转化整体较低，但收入贡献有明确的人群、平台和站内链路特征。由于召回后 7 日窗口内存在较多历史订单负向流水/退款冲正，本文主结论使用“召回归因口径”，不直接使用现金流净收入判断召回效果。

1. 7 日会员付费规模较小，收入集中在少数转化用户。

   2-4 月共召回 690,277 人，7 日内会员支付用户 376 人，支付率为 0.0545%。7 日会员正向支付收入为 18,258.89，召回归因净收入为 16,044.99，折算单付费用户归因净收入约 42.67。

2. 现金流净收入被历史订单负向流水/退款冲正明显拉低。

   7 日退款金额为 -9,713.90，其中历史订单负向流水/退款冲正为 -7,500.00，占 7 日退款金额的 77.2%。这部分仅涉及 19 名用户，占召回用户 0.0028%，属于少量用户多笔历史订单集中退款。若直接看现金流净收入，结果为 8,544.99，会比召回归因净收入低 7,500.00。

3. 收入贡献高度集中在三类核心人群。

   新经济腰尾、传统主流一线、新经济头部合计贡献 7 日归因净收入 88.6%，贡献召回后累计归因净收入 83.5%。其中新经济腰尾短期响应最强，新经济头部累计价值最高，传统主流一线主要依靠规模贡献。

4. Android 适合做召回后短期强承接，iOS 更适合长周期经营。

   在核心人群中，Android 7 日支付率约为 iOS 的 4.4-6.4 倍；但 iOS 核心人群 7 日后长尾收入占比普遍超过 90%，不宜只用 7 日窗口判断 iOS 价值。

5. 站内付费链路的关键不是 content 回访，而是 platform 深度行为和 member 权益承接。

   未付费用户 content 访问率已经达到 97.94%，说明内容回访不是主要缺口。付费用户 member 访问率为 91.49%，未付费用户仅 20.67%；付费用户 member 人均停留约为未付费用户的 51.1 倍，是当前会员转化最关键的承接节点。

## 2. 数据口径与归因方法

结论：本次分析的关键口径是“先定义召回用户，再在用户自己的召回窗口内做会员收入归因”。历史订单负向流水/退款冲正单独拆出，用于解释现金流波动，不用于扣减召回带来的新订单收入。

### 2.1 召回用户口径

| 项目 | 口径 |
|---|---|
| 召回时间 | 2026-02-01 至 2026-04-30 |
| 召回来源 | `dwm.dw_growth_user_sms_recall_di` |
| 活跃关联 | 与 `dwm.dw_growth_user_active_di` 按 `uid + d` 关联 |
| 用户限制 | `silent_days >= 30`，且召回当天 `is_member = 0` |
| 底表粒度 | 一行一个召回用户 |
| 多次召回处理 | 取 2-4 月首次召回日期作为 `召回日期` |

说明：`is_member = 0` 只表示召回当天会员快照为非会员，不代表用户历史上没有买过会员。因此召回后窗口内可能出现历史订单退款或冲正。

### 2.2 收入口径

| 项目 | 口径 |
|---|---|
| 收入表 | `dwd.dw_member_deal_all_da` |
| 正向支付 | 当前主口径为 `order_type IN (1, 3)` |
| 退款/冲正 | `order_type IN (4, 5)` |
| 剔除项 | `mem_id IN (6, 10)`、iOS 外币异常、黑产用户收入 |
| 黑产识别 | `dim.dim_user.is_blocked` |

说明：已确认 `order_type = 2` 为线下订单，但当前底表主收入逻辑尚未将其纳入会员正向支付。若后续确认线下订单也应计入会员收入，需要同步修改底表和报告结果。

### 2.3 归因逻辑

| 口径 | 定义 | 用途 |
|---|---|---|
| 7 日窗口 | 每个用户的 `召回日期` 至 `召回日期 + 6` | 约束短期召回归因 |
| 现金流口径 | 窗口内正向支付 + 窗口内所有退款/冲正 | 观察这批用户窗口内真实流水 |
| 召回归因口径 | 召回后新支付订单收入 + 这些新订单对应的退款 | 判断召回动作带来的会员收入 |
| 历史订单负向流水/退款冲正 | 退款入账在召回窗口内，但原支付日期早于召回日期 | 解释现金流与归因收入的差异 |

归因判断的核心是：退款对应的原支付日期 `origin_pay_date` 必须落在召回窗口内，才扣减召回归因收入。

## 3. 整体收入表现

结论：7 日窗口内有真实会员转化，但绝对转化率偏低；历史订单负向流水/退款冲正是现金流净收入和召回归因净收入差异的主要来源。

| 指标 | 数值 |
|---|---:|
| 召回用户数 | 690,277 |
| 7 日会员支付用户数 | 376 |
| 7 日会员支付率 | 0.0545% |
| 7 日正向支付收入 | 18,258.89 |
| 7 日退款金额_现金流口径 | -9,713.90 |
| 其中：7 日历史订单负向流水/退款冲正 | -7,500.00 |
| 其中：7 日召回后新订单退款 | -2,213.90 |
| 7 日会员净收入_现金流口径 | 8,544.99 |
| 7 日会员净收入_召回归因口径 | 16,044.99 |

数据表现：

- 7 日支付用户只有 376 人，说明短信电话召回后的会员转化是低频事件，单日或短周期波动容易被少数订单和退款放大。
- 7 日正向支付收入 18,258.89，扣除召回后新订单退款后，召回归因净收入为 16,044.99。
- 历史订单负向流水/退款冲正为 -7,500.00，占全部 7 日退款金额 77.2%，这是现金流净收入偏低的主因。
- 历史订单负向流水/退款冲正只涉及 19 名用户，占召回用户 0.0028%；召回后 7 日新订单退款涉及 38 名用户，占召回用户 0.0055%。

解释：

现金流口径回答的是“这批召回用户在窗口内实际发生了多少流水”，可以用于财务波动监控；召回归因口径回答的是“召回后新产生的会员订单贡献了多少收入”，更适合判断召回效果。因此后续人群、平台、渠道分析均以召回归因口径为主。

### 3.1 历史订单退款深追

结论：7 日历史订单退款不是大面积召回用户行为，而是极少数用户的多笔历史订单集中退款。若后续能在召回前识别并排除这类用户，召回量级几乎不变，会员归因收入不变，但现金流口径会明显改善。

| 召回后7日新订单退款 | 38 | 0.0055% | -2,213.90 |
| 未知原支付订单退款 | 0 | 0.0000% | 0.00 |

| 人群 | 召回用户数 | 7日正向支付用户数 | 7日正向支付收入 | 7日退款金额_现金流口径 | 7日历史订单退款金额 | 7日现金流净收入 | 7日召回归因净收入 | 召回后累计归因净收入 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| 全量召回用户 | 690,277 | 376 | 18,258.89 | -9,713.90 | -7,500.00 | 8,544.99 | 16,044.99 | 175,135.19 |
| 拟排除：7日历史订单退款用户 | 19 | 8 | 1,264.00 | -8,764.00 | -7,500.00 | -7,500.00 | 0.00 | 0.00 |

数据表现：

- 这 19 人虽然有 8 人在 7 日内发生正向支付，正向支付收入为 1,264.00，但同批新订单退款也为 -1,264.00，因此 7 日召回归因净收入为 0。
- 这 19 人召回后累计归因净收入也为 0，说明在当前统计期内没有给主归因口径贡献会员收入。
- 排除这 19 人后，召回用户数只减少 0.0028%，但 7 日现金流净收入会从 8,544.99 提升到 16,044.99；7 日召回归因净收入和召回后累计归因净收入保持不变。

策略含义：

从结果看，排除这类用户对会员归因收入没有负面影响，并能减少历史退款对现金流口径的扰动。但这 19 人是“召回后发生历史退款”的结果人群，不能直接作为上线前排除规则。后续如要用于召回策略，需要基于召回前可识别特征构建规则，例如历史自动续费订单、近期待退款/冲正风险、老订单退款记录、自动续费补扣状态等，再验证覆盖率和误伤收入。

结论：付费用户和未付费用户的差异主要不在是否回访 content，而在 jobs、platform、member 的深度行为，尤其是 member 权益承接。

链路假设：

```text
短信电话召回
→ 用户回访
→ jobs 求职相关访问
→ platform 搜索 / IM / 平台能力使用加深
→ member 权益页或会员承接页
→ 会员支付
```

解释：

当前数据更支持“需求被重新激活后，通过 platform 和 member 承接完成会员转化”的判断。member 是最接近支付决策的关键节点，后续优化重点应放在 platform 到 member 的引导、member 权益页表达、访问 member 后未支付用户的二次承接。

## 8. 策略建议

结论：后续策略不建议只按召回规模加量，而应按“人群价值 × 平台转化周期 × 站内承接节点”组合优化。

| 方向 | 建议 |
|---|---|
| 新经济腰尾 | 短期响应最强，优先做 Android 7 日内强承接，强化会员权益、价格刺激和下单链路 |
| 新经济头部 | 累计价值最高，尤其适合 iOS 长周期经营，建议做 14 日/30 日二次触达和权益提醒 |
| 传统主流一线 | 规模最大，建议保量优化，重点提升 platform 到 member 的到达率和支付率 |
| 其他主流行业 | 规模小但累计价值较好，适合小规模扩量测试，验证放量后效率是否保持 |
| 学生 / 传统行业其他 | 整体收入效率偏弱，建议降频或改用低成本触达 |
| phone | 继续作为主渠道，优先承接核心三类人群 |
| wechat / push | 支付率不低但收入规模小，建议结合成本看 ROI，再决定是否扩量 |
| other | 拆解 `recall_recent_*` 策略标签，不直接按渠道解释 |
| 站内承接 | 在 jobs、platform 场景下增强会员权益露出；对进入 platform 但未进入 member 的用户做权益页引导；对访问 member 未支付用户做二次提醒 |
| 历史退款风险用户 | 先不直接按结果人群排除，后续用召回前可识别的自动续费、老订单退款、待退款/冲正风险特征做小流量验证 |

## 9. 数据边界与后续补充

结论：当前数据足以支持方向判断，但不适合单独做因果归因或 ROI 结论。后续需要补齐成本、窗口完整性和退款明细验证。

数据边界：

- 本文是召回后行为与收入归因分析，不是 A/B 实验，不能单独证明召回动作的因果增量。
- 当前收入统计截止为 2026-04-30。如 4 月下旬召回用户的 7 日窗口未完整覆盖，严谨口径应将收入统计延长至 2026-05-06，或仅分析 `召回日期 <= 2026-04-24` 的用户。
- 当前主收入逻辑未纳入 `order_type = 2` 线下订单。若业务确认线下订单应计入会员收入，需要重跑底表和报告。
- 当前缺少触达成本，本文不直接判断 ROI，仅解释收入侧变化和优化方向。
- 历史订单负向流水/退款冲正已从召回归因口径中拆出，并已确认主要是少量用户多笔历史订单集中退款。若要用于后续召回排除，需要改用召回前可识别特征做规则验证，避免使用召回后结果标签造成口径泄漏。

后续建议：

1. 基于召回前可识别特征构建历史退款风险规则，例如历史自动续费、近期待退款/冲正风险、老订单退款记录，并小流量验证误伤收入。
2. 拆 project 级路径，例如 `platform/im`、`platform/search`、`member/member`、`member/sales_member`、`jobs/jobs`、`jobs/seeker`。
3. 对 iOS 核心人群补充 14 日和 30 日归因收入，验证长尾承接价值。
4. 对 phone、wechat、push 补充触达成本，形成收入、成本、ROI 一体化判断。
5. 拆解 other 中的 `recall_recent_*` 策略标签，判断哪些策略包贡献真实会员收入。
