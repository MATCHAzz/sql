# 2026 年 2-4 月短信电话召回会员付费分析报告

## 1. 核心结论

2026 年 2-4 月短信电话召回用户的会员短期付费转化整体较低，但收入贡献有明确的人群、平台和站内链路特征。由于召回后 7 日窗口内存在较多历史订单负向流水/退款冲正，本文主结论使用“召回归因口径”，不直接使用现金流净收入判断召回效果。

1. 7 日会员付费规模较小，收入集中在少数转化用户。

   2-4 月共召回 690,277 人，7 日内会员支付用户 376 人，支付率为 0.0545%（376 / 690,277）。7 日会员正向支付收入为 18,258.89，召回归因净收入为 16,044.99，折算单付费用户归因净收入约 42.67（16,044.99 / 376）。

2. 现金流净收入被历史订单负向流水/退款冲正明显拉低。

   7 日退款金额为 -9,713.90，其中历史订单负向流水/退款冲正为 -7,500.00，占 7 日退款金额的 77.2%（-7,500.00 / -9,713.90）。这部分仅涉及 19 名用户，占召回用户 0.0028%（19 / 690,277），属于少量用户多笔历史订单集中退款。若直接看现金流净收入，结果为 8,544.99，会比召回归因净收入低 7,500.00。

3. 收入贡献高度集中在三类核心人群。

   新经济腰尾、传统主流一线、新经济头部合计贡献 7 日归因净收入 88.6%（14,220.90 / 16,044.99），贡献召回后累计归因净收入 83.5%（146,249.23 / 175,135.19）。其中新经济腰尾短期响应最强，新经济头部累计价值最高，传统主流一线主要依靠规模贡献。

4. Android 适合做召回后短期强承接，iOS 更适合长周期经营。

   核心三类人群合并看，Android 7 日支付率为 0.0935%（222 / 237,545），iOS 为 0.0178%（53 / 298,352），Android 约为 iOS 的 5.3 倍；iOS 核心人群 7 日后长尾收入占比 93.6%（89,365.13 / 95,509.23），不宜只用 7 日窗口判断 iOS 价值。

5. 站内付费链路的关键不是 content 回访，而是 platform 深度行为和 member 权益承接。

   未付费用户 content 访问率已经达到 97.94%（约 674,710 / 688,901），说明内容回访不是主要缺口。付费用户 member 访问率为 91.49%（344 / 376），未付费用户仅 20.67%（约 142,396 / 688,901）；付费用户 member 人均停留约为未付费用户的 51.1 倍（100.11 / 1.96），是当前会员转化最关键的承接节点。

## 2. 数据口径与归因方法

结论：本次分析的关键口径是“先定义召回用户，再在用户自己的召回窗口内做会员收入归因”。历史订单负向流水/退款冲正单独拆出，用于解释现金流波动，不用于扣减召回带来的新订单收入。

### 2.1 召回用户口径

| 项目 | 口径 |
|---|---|
| 召回时间 | 2026-02-01 至 2026-04-30 |
| 召回来源 | `dwm.dw_growth_user_sms_recall_di` |
| 活跃关联 | 与 `dwm.dw_growth_user_active_di` 按 `uid + d` 关联 |
| 用户限制 | `silent_days >= 30`，且召回当天 `is_member = 0` |
| 底表粒度 | 一行一个召回用户 |
| 多次召回处理 | 取 2-4 月首次召回日期作为 `召回日期` |

说明：`is_member = 0` 只表示召回当天会员快照为非会员，不代表用户历史上没有买过会员。因此召回后窗口内可能出现历史订单退款或冲正。

### 2.2 收入口径

| 项目 | 口径 |
|---|---|
| 收入表 | `dwd.dw_member_deal_all_da` |
| 正向支付 | 当前主口径为 `order_type IN (1, 3)` |
| 退款/冲正 | `order_type IN (4, 5)` |
| 剔除项 | `mem_id IN (6, 10)`、iOS 外币异常、黑产用户收入 |
| 黑产识别 | `dim.dim_user.is_blocked` |

说明：已确认 `order_type = 2` 为线下订单，但当前底表主收入逻辑尚未将其纳入会员正向支付。若后续确认线下订单也应计入会员收入，需要同步修改底表和报告结果。

### 2.3 归因逻辑

| 口径 | 定义 | 用途 |
|---|---|---|
| 7 日窗口 | 每个用户的 `召回日期` 至 `召回日期 + 6` | 约束短期召回归因 |
| 现金流口径 | 窗口内正向支付 + 窗口内所有退款/冲正 | 观察这批用户窗口内真实流水 |
| 召回归因口径 | 召回后新支付订单收入 + 这些新订单对应的退款 | 判断召回动作带来的会员收入 |
| 历史订单负向流水/退款冲正 | 退款入账在召回窗口内，但原支付日期早于召回日期 | 解释现金流与归因收入的差异 |

归因判断的核心是：退款对应的原支付日期 `origin_pay_date` 必须落在召回窗口内，才扣减召回归因收入。

## 3. 整体收入表现

结论：7 日窗口内有真实会员转化，但绝对转化率偏低；历史订单负向流水/退款冲正是现金流净收入和召回归因净收入差异的主要来源。

| 指标 | 数值 |
|---|---:|
| 召回用户数 | 690,277 |
| 7 日会员支付用户数 | 376 |
| 7 日会员支付率 | 0.0545%（376 / 690,277） |
| 7 日正向支付收入 | 18,258.89 |
| 7 日退款金额_现金流口径 | -9,713.90 |
| 其中：7 日历史订单负向流水/退款冲正 | -7,500.00 |
| 其中：7 日召回后新订单退款 | -2,213.90 |
| 7 日会员净收入_现金流口径 | 8,544.99 |
| 7 日会员净收入_召回归因口径 | 16,044.99 |

数据表现：

- 7 日支付用户只有 376 人，说明短信电话召回后的会员转化是低频事件，单日或短周期波动容易被少数订单和退款放大。
- 7 日正向支付收入 18,258.89，扣除召回后新订单退款后，召回归因净收入为 16,044.99。
- 历史订单负向流水/退款冲正为 -7,500.00，占全部 7 日退款金额 77.2%（-7,500.00 / -9,713.90），这是现金流净收入偏低的主因。
- 历史订单负向流水/退款冲正只涉及 19 名用户，占召回用户 0.0028%（19 / 690,277）；召回后 7 日新订单退款涉及 38 名用户，占召回用户 0.0055%（38 / 690,277）。

解释：

现金流口径回答的是“这批召回用户在窗口内实际发生了多少流水”，可以用于财务波动监控；召回归因口径回答的是“召回后新产生的会员订单贡献了多少收入”，更适合判断召回效果。因此后续人群、平台、渠道分析均以召回归因口径为主。

- 时间分布前置：7 日内已经发生 80 笔历史退款，占累计历史退款笔数 70.2%（80 / 114），金额占累计历史退款金额 52.1%（7,500 / 14,392），说明主要扰动集中在召回后短窗口内。
- 7 日后增量更偏长尾：7-13 天新增约 2 人、2 笔、-386；14-29 天新增约 7 人、7 笔、-1,256；30 天后至统计截止日再新增约 24 人、25 笔、-5,250。拉长窗口后人数继续增加，但分布更零散，不像 7 日内那样集中。

整体看，历史退款不是大面积人群问题，而是少量用户多笔历史订单集中退款带来的金额扰动；策略上更适合做风险监控和小流量验证，不适合按大包直接排除。

召回前风险人群包分析前提：

说明：下面的人群包和补扣支付细拆，目的不是证明“补扣导致退款”，而是回测能否用召回前已经可见的订单特征，提前识别会在召回后窗口内产生历史订单负向流水/退款冲正的用户。

- 入包条件只使用召回日期之前可见的信息，包括历史补扣支付、历史自动续费、老订单支付、历史退款/冲正等，不使用“召回后发生历史退款”这个结果标签。
- 评估目标是降低现金流口径的历史退款扰动，不是修正召回归因收入。历史订单负向流水/退款冲正已经被排除在召回归因口径之外。
- 判断一条规则是否可直接排除，核心看三件事：候选包规模是否足够小、能覆盖多少 7 日历史退款金额、可能误伤多少召回归因收入。
- `可能误伤累计归因净收入` 表示如果把这个候选包从召回中剔除，可能损失的召回后累计归因净收入。它不是确定损失，只是基于历史回测的风险上限参考。
- 当前分析是历史回测，不是 A/B 实验；任何排除或降频策略上线前仍需要小流量验证。

因此，`补扣支付` 不建议作为直接排除规则；更适合作为现金流风险监控标签、小流量降频验证标签，或在成本较低的触达渠道中做差异化承接。若业务只接受极低误伤，可以把 `近30天有补扣` 作为微型保守排除或低成本触达候选，但它只能覆盖 5.3% 的 7 日历史退款金额，不能作为主排除策略。`近90天有补扣` 可以作为小流量降频验证候选，但需要同时观察历史退款减少、触达成本节省、7 日归因收入和累计归因收入误伤。

结论：后续策略不建议只按召回规模加量，而应按“人群价值 × 平台转化周期 × 站内承接节点”组合优化。

|---|---|
| 新经济腰尾 | 短期响应最强，优先做 Android 7 日内强承接，强化会员权益、价格刺激和下单链路 |

## 9. 数据边界与后续补充

结论：当前数据足以支持方向判断，但不适合单独做因果归因或 ROI 结论。后续需要补齐成本、窗口完整性和退款明细验证。

数据边界：

- 本文是召回后行为与收入归因分析，不是 A/B 实验，不能单独证明召回动作的因果增量。
- 当前收入统计截止为 2026-04-30。如 4 月下旬召回用户的 7 日窗口未完整覆盖，严谨口径应将收入统计延长至 2026-05-06，或仅分析 `召回日期 <= 2026-04-24` 的用户。
- 当前主收入逻辑未纳入 `order_type = 2` 线下订单。若业务确认线下订单应计入会员收入，需要重跑底表和报告。
- 当前缺少触达成本，本文不直接判断 ROI，仅解释收入侧变化和优化方向。
- 历史订单负向流水/退款冲正已从召回归因口径中拆出，并已确认主要是少量用户多笔历史订单集中退款。若要用于后续召回排除，需要改用召回前可识别特征做规则验证，避免使用召回后结果标签造成口径泄漏。

后续建议：

1. 基于召回前可识别特征构建历史退款风险规则，例如历史自动续费、近期待退款/冲正风险、老订单退款记录，并小流量验证误伤收入。
2. 拆 project 级路径，例如 `platform/im`、`platform/search`、`member/member`、`member/sales_member`、`jobs/jobs`、`jobs/seeker`。
3. 对 iOS 核心人群补充 14 日和 30 日归因收入，验证长尾承接价值。
4. 继续从 `补扣支付` 和高频自动续费人群中寻找更小的召回前可识别组合规则，重点评估覆盖历史退款金额、候选包规模和误伤累计归因收入。
5. 对 phone、sms、wechat、push 补充触达成本，形成收入、成本、ROI 一体化判断。
6. 定期校验 `recall_tags` 到渠道的映射规则，避免 `recent` 这类短信策略标签被误归入 other。
