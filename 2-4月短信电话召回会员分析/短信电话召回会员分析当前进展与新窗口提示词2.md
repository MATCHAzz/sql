## 4. 退款问题与最终处理口径

最初发现的问题：

- 7 日净收入中存在负数。
- 明细排查发现一些用户在召回后 7 日内发生大量退款。
- 典型样例是用户历史自动续费订单在 2026 年召回后发生退款/冲正入账。

示例逻辑：

```text
2023/2024 用户自动续费支付会员
2026-02/04 用户被召回，当天 is_member = 0
2026-02/04 历史订单退款/冲正入账
```

这类退款的特点：

- 原支付时间在召回前，甚至可能早于召回很久；
- 退款入账时间落在召回后 7 日窗口内；
- 如果只按 `income_ts` 落窗，会导致 7 日现金流净收入被历史退款拉低。

因此已将收入拆成两套口径。

### 4.1 现金流口径

定义：

```text
召回后窗口内发生的正向支付 + 窗口内发生的所有退款
```

用途：

```text
观察这批召回用户在窗口内真实发生的现金流。
```

这个口径可以为负。

### 4.2 召回归因口径

定义：

```text
召回后新支付订单收入 + 这些召回后新订单对应的退款
```

核心判断：

```text
退款对应的原支付日期 origin_pay_date 必须在召回后窗口内，才扣减召回收入。
```

用途：

```text
判断短信电话召回带来的会员收入。
```

后续主结论使用召回归因口径。

## 13. 当前遇到的 ClickHouse 注意事项

当前 ClickHouse 版本：

```text
21.3.6.55
```

已遇到的问题：

1. `JOIN ON` 不支持非等值条件。

错误形式：

```sql
ON a.uid = b.uid
AND a.d BETWEEN b.recall_date AND b.recall_date + 6
```

修正方式：

```sql
ON a.uid = b.uid
```

时间条件放到：

```sql
sumIf(...)
WHERE ...
```

2. 多层 CTE + 中文别名容易报 Missing columns。

修正方式：

- 中间过程尽量用英文别名；
- 最终 SELECT 再输出中文列名；
- 尽量减少 `WITH cte AS (...)` 多层嵌套；
- 必要时将查询写扁平。
